# Inspiration — reference sites

Show this to the user when they have no visual direction in mind. Asking "what
style would you like?" produces a shrug; asking "closer to The Pudding or closer
to a Stripe report?" produces an answer in one sentence.

Offer three or four that suit the format and the audience, say in a line what
each would mean for their document, and build to whichever they point at. Do not
paste the whole list.

These are references for *approach* — layout, typography, how evidence is
presented — not templates to copy. Never reproduce a site's branding.

## Editorial and report

| Reference | What to take from it |
|---|---|
| **The Pudding** — pudding.cool | Essay-driven data journalism. Prose and exhibit alternate; the chart arrives exactly where the sentence needs it. The model for a report that argues rather than lists. |
| **Bloomberg Graphics** — bloomberg.com/graphics | Dense, confident charts with editorial voice. Annotation directly on the plot rather than in a legend. Good for a numbers-heavy executive read. |
| **The Upshot** — nytimes.com/section/upshot | Annotated charts inline with argument, and unusually careful about what a number does and does not show. Study the caveat sentences. |
| **Our World in Data** — ourworldindata.org | Chart-first explainers with sourcing visible at every step. The reference for making method legible without drowning the reader. |
| **FT Visual & Data Journalism** — ft.com/visual-and-data-journalism | Small multiples, disciplined restricted palettes, and restraint. Take the colour discipline especially. |
| **Stripe Press / annual updates** — press.stripe.com | Generous whitespace, one strong typeface, quiet confidence. The reference for a corporate document that does not look like a template. |
| **Linear changelog** — linear.app/changelog | Product-report tone with tight visual rhythm. Good model for a recurring update people actually read. |

## Interactive and data story

| Reference | What to take from it |
|---|---|
| **Distill** — distill.pub | The standard for explorable explanations. Interactive figures with obvious affordances, and text that tells you what to try. |
| **Observable D3 gallery** — observablehq.com/@d3/gallery | Canonical D3 patterns with source. Start here for chart mechanics rather than inventing them. |
| **Explorable Explanations** — explorabl.es | The Bret Victor lineage — the argument for letting a reader manipulate a model instead of reading its conclusion. |
| **Nicky Case** — ncase.me | Playable explanations that stay warm and legible. Excellent on pacing: one idea, one interaction, then move on. |
| **Setosa** — setosa.io | Interactive explanations of single concepts. The reference for "one control, one insight". |
| **Amelia Wattenberger** — wattenberger.com | D3 plus genuine explanatory design. Strong on making an interaction's purpose obvious without instructions. |
| **three.js examples** — threejs.org/examples | Canonical WebGL patterns with source. The right starting point for anything 3D. |
| **Bruno Simon** — bruno-simon.com | 3D used as narrative rather than decoration. Take the restraint about when 3D is worth its cost. |
| **Nadieh Bremer** — visualcinnamon.com | Bespoke visual identity in data work. For when a report should look like nobody else's. |

## Reading a reference back to the user

Translate the pick into concrete decisions before you build, and confirm them:

> Pudding-style, then — serif headline, generous measure, charts breaking wider
> than the text column, each one annotated where the argument needs it. Cool
> greys with one accent for the series that matters.

That sentence is the brief. If they correct it, you have saved a full rebuild.
